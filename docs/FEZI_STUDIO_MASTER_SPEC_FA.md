# FEZI STUDIO — MASTER COMPLETION PROMPT

تو توسعه‌دهنده اصلی پروژه **FEZI Studio — فضی استودیو** هستی.

هدف، تکمیل یک وب‌سایت واحد مبتنی بر Node.js 22 است. باید تمام امکانات موجود حفظ شوند و بدون حذف فایل‌ها، صفحات، لوگوی رسمی یا قابلیت‌های قبلی، سیستم یکپارچه شود.

### FEZI Agent

مأموریت اصلی FEZI Agent ساخت، ویرایش، نصب، تست و انتشار وب‌سایت و وب‌اپ است.

- اسکیل‌های معتبر پلاگین‌های FEZI Studio، Premium، Super Plugin و GitFez را به ایجنت متصل کن.
- ساخت پروژه، ویرایش فایل، پیش‌نمایش، اجرای تست، GitHub، نصب روی هاست و Rollback را یکپارچه کن.
- یک MCP مستقل با احراز هویت برای FEZI Agent داشته باش.
- بخش Shell را فقط در محیط مجاز و محدودشده فراهم کن.
- نتیجه هر عملیات را با تست واقعی تأیید کن.

### Telegram Bots

یک ربات مرکزی به نام Telegram Bots طراحی کن که کاربران را برای ساخت ربات جدید راهنمایی کند و مدیریت ربات‌های متصل را انجام دهد.

قابلیت‌ها شامل ساخت منو، فرمان، پاسخ خودکار، ویرایش، خروجی پروژه و فهرست ربات‌های ساخته‌شده باشد.

از Node.js، grammY، Telegraf و aiogram پشتیبانی کن.

ساخت شناسه و توکن ربات جدید از طریق BotFather انجام شود. توکن‌ها فقط در محیط امن سرور ذخیره شوند.

در پیام‌های ربات‌های ساخته‌شده، امضای FEZI Studio و در صورت تنظیم، لینک وب‌سایت نمایش داده شود.

### Free AI Models

مدل‌ها و ابزارهای رایگان را از منابع رسمی OpenRouter، Hugging Face و GitHub پیدا کن.

- برای استفاده پیش‌فرض از OpenRouter فقط مدل‌های رایگان را انتخاب کن.
- مدل‌های پولی بدون اجازه فعال نشوند.
- نسخه‌ها، لایسنس، حجم و قابلیت‌های مدل‌ها را بررسی کن.
- مدل کشف‌شده را بدون تست، نصب‌شده یا فعال معرفی نکن.
- دکمه انتخاب و مشاهده اطلاعات مدل در رابط کاربری ایجاد کن.

### Autonomous Updates

یک زمان‌بند ۲۴ ساعته طراحی کن که روزانه مدل‌های جدید، ابزارهای MCP، اسکیل‌ها، تغییرات GitHub و آسیب‌پذیری‌های شناخته‌شده را بررسی کند.

متادیتای تأییدشده را به کاتالوگ اضافه کند. تغییرات کد ابتدا در محیط آزمایشی بررسی شوند و انتشار فقط طبق مجوزهای از پیش تعیین‌شده انجام شود. سیستم باید گزارش و Rollback داشته باشد.

### Additional AI Frameworks

معماری توسعه‌پذیر برای Transformers، smolagents، LangChain، LiteLLM، Flowise، n8n و Open WebUI آماده کن. اتصال هر مورد باید پس از بررسی سازگاری، مجوز استفاده و تست واقعی انجام شود.

### Final Requirements

وب‌سایت باید روی یک دامنه و با یک پروژه اصلی کار کند. رابط فارسی و انگلیسی، موبایل، امنیت، احراز هویت، عملکرد و SEO بررسی شوند.

هیچ توکن خصوصی در GitHub یا فایل عمومی قرار نگیرد. قبل از انتشار، تمام تست‌ها اجرا شوند و برای هر قابلیت وضعیت واقعی READY، CONFIG REQUIRED یا PLANNED ثبت شود.

**خروجی نهایی:** سورس کامل، فایل Docker، GitHub Actions، راهنمای نصب فارسی، گزارش تست‌ها و نسخه آماده استقرار بدون حذف قابلیت‌های قبلی.
