# نقشه اجرایی FEZI Agent برای ساخت پنج میلیون اسکیل متفاوت

## واقعیت امروز
- یک پلاگین اختصاصی ChatGPT با نام `fezi-agent-builder` و نسخه 0.1.0 ایجاد شده است.
- ۴۹ فایل SKILL.md اصلی در آن وجود دارد. این اسناد از نظر فرمت و محتوای پایه ساخته شده‌اند؛ اتصال end-to-end همه به ابزارهای واقعی هنوز تأیید نشده است.
- هدف بلندمدت ۵٬۰۰۰٬۰۰۰ مهارتِ **مستقل و اعتبارسنجی‌شده** است؛ این عدد موجودی واقعی نیست.
- سورس فعلی سایت پیش از این شامل ۲۰ مهارت محلی بوده است؛ اکنون ۴۹ سند جدید اضافه شده و در آزمون محلی ۶۹ سند قابل فهرست‌کردن است.

## معماری لازم

### لایه اول: مهارت‌های هسته (Core)
اسکیل‌های کوچک و کاربردی سایت‌سازی، کدنویسی، تحلیل، UI، تست، GitHub، استقرار، Telegram، MCP و مدل AI؛ در حافظه محدود FEZI Agent نگهداری شوند.

### لایه دوم: مهارت‌های قابل کشف (Registry)
یک بانک Postgres شامل کلید مهارت، عنوان، نوع کار، نیازمندی و ابزار، status، source/license، revision، content_hash و وضعیت تست. متن کامل در storage قابل جست‌وجو ذخیره شود. فقط مهارت‌های مناسب درخواست فعلی وارد پنجره متن AI شوند.

### لایه سوم: کارخانه تولید و تست (Skill Factory)
صف‌های `discovery`, `draft`, `deduplicate`, `verify`, `eval`, `review`, `publish`. مهارت‌ها تا هنگام خروج از این مراحل فعال تلقی نشوند.

### لایه چهارم: ابزارهای واقعی
MCP/OAuth/GitHub/SSH/Worker فقط با دسترسی صاحب پروژه فعال شوند. اسکیل راهنماست؛ ابزارِ اجراگر جدا است. `READY` باید با اجرای واقعی و log مستند اثبات شود.

## نمونه اسکیمای ذخیره‌سازی

```sql
CREATE TABLE skills (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  objective TEXT NOT NULL,
  domain TEXT NOT NULL,
  content_hash CHAR(64) NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('DISCOVERED','DRAFT','VALIDATED','OPERATIONAL','DEPRECATED')),
  source_url TEXT,
  source_license TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  reviewed_at TIMESTAMPTZ,
  test_result JSONB NOT NULL DEFAULT '{}'::jsonb,
  version INTEGER NOT NULL DEFAULT 1
);
CREATE UNIQUE INDEX skills_content_hash_uq ON skills(content_hash);
CREATE INDEX skills_domain_status_idx ON skills(domain,status);
```

این اسکیمای مرجع است، نه جدولی که ادعا شود اکنون روی سرور اجرا شده است. برای پیشگیری از مشابهت معنایی، hash به‌تنهایی کافی نیست: باید بردار معنا، آزمون تطبیق هدف و بازبینی نمونه نیز انجام شود.

## معیار ضدتورم تعداد
- تغییر اسم، زبان، نسخه کتابخانه یا پارامتر بدون تفاوت واقعی روش و خروجی، **اسکیل جدید نیست**.
- یک اسکیل فاقد تست مستقل، حداکثر DRAFT است؛ در آمار validated نمی‌آید.
- یک اسکیل با سند صحیح ولی بدون MCP/Worker فعال، OPERATIONAL نیست.
- کاندیدای ردشده/تکراری قابل نگهداری است اما به شمارنده معتبر اضافه نمی‌شود.
- هر ۱۰۰۰ مهارت تازه، نمونه‌ای از عملکرد و همپوشانی برای بررسی مستقل انتخاب شود.

## ظرفیت و هزینه
۵٬۰۰۰٬۰۰۰ فایل با میانگین ۵ کیلوبایت تقریباً ۲۵ گیگابایت متن خام نیاز دارد. متن تنها بخش کوچکی از هزینه است: ایندکس، تست‌ها، نسخه‌های مختلف، بکاپ، جستجو، اجرای مدل‌ها، صف‌ها و نگهداری نیز منابع نیاز دارند. این هدف را با یک پردازه Node که حداکثر ۱۶۰۰ فایل را بارگذاری می‌کند نباید پیاده کرد.

## فرمان شروع اجرایی
1. ثبت موجودی واقعی اسکیل‌ها و وضعیت هر اسکیل.
2. کار کردن ۴۹ مهارت اولیه در سناریوی واقعی ساخت/ادیت/تست سایت.
3. راه‌اندازی Postgres/Storage و جدول داده‌ها.
4. طراحی Skill Creator با خروجی DRAFT و تست محتوا.
5. تعریف صف کشف روزانه، بدون مجوز خودکار انتشار تغییرات پرریسک.
6. شروع فاز ۱ تا ۱۰۰۰ اسکیل واقعی و ثبت نرخ رد/تکرار/موفقیت.

**توجه:** رشد قابل راستی‌آزمایی یک کتابخانه ۱۰۰۰ اسکیل مفید، از تولید ساختگی چند میلیون فایل با عنوان‌های تکراری ارزشمندتر است. وقتی کیفیت حفظ شود می‌توان فازهای بعدی را توسعه داد.
