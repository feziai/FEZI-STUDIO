# FEZI Studio v1.01 — خرید و اتصال کیف پول (افزایشی)

## در این مرحله چه چیزهایی واقعاً اضافه شده؟

- `/purchase` صفحه خرید مستقل از بخش رایگان FEZI Agent؛ لینک در هدر و لندینگ فارسی و انگلیسی
- انتخاب ۱۰، ۲۵، ۵۰ و ۱۰۰ دلار یا مبلغ دلخواه (حداقل ۱۰ دلار)
- انتخاب ارز/شبکه از ۲۲ شبکه موجود پروژه، همراه نشان رنگی ارز، آدرس و QR **صرفاً پیش‌نمایش**
- بررسی ابتدایی قالب آدرس و مخفی‌سازی QR در شبکه‌های دارای آدرس نامعتبر؛ اعتبارسنجی رشته مالکیت را اثبات نمی‌کند
- اتصال کیف پول EVM نصب‌شده با `eth_requestAccounts` و شناسایی چند کیف پول با EIP-6963؛ هر اتصال منوط به تأیید کاربر
- مسیر رسمی `Trust Wallet` برای بازکردن مرورگر داخلی کیف پول در گوشی؛ برای دیگر کیف پول‌ها وب‌سایت رسمی و اتصال در مرورگر داخلی
- معرفی Trust Wallet، Coinbase Wallet، MetaMask، Rainbow، Phantom، OKX Wallet، Exodus و TokenPocket
- `/api-keys`، `/api-keys/docs`، `/api/api-keys/models`, `/api/api-keys/account`, `/api/api-keys/topup`, `/api/api-keys/keys`, `/api-keys/sitemap.xml` به سرور اصلی متصل شدند
- `/admin/api-providers`: نمایش وجود یا نبود متغیرهای محرمانه **فقط با ورود ادمین**؛ هیچ رمز یا API key در پاسخ API نیست

## مواردی که هنوز واقعی و خودکار نیستند

- اتصال WalletConnect/Reown از مرورگر موبایل خارج از مرورگر کیف پول؛ نیازمند **Reown Project ID**، SDK و تست دستگاه
- تأیید خودکار و غیرقابل جعل انتقال رمزارز. برای این موضوع باید سرویس بررسی تراکنش/نود RPC، بررسی قرارداد توکن، مبلغ، دریافت‌کننده، شمار تأییدهای زنجیره، شناسه تراکنش و جلوگیری از استفاده مجدد از تراکنش پیاده‌سازی و ممیزی شود
- اعتبار مثبت در حساب، برداشت API، خرید مدل پولی و شارژ موفق — همگی عمداً غیرفعال‌اند تا از ادعای کاذب پرداخت جلوگیری شود
- مالکیت آدرس‌های مقصد قبلی به صورت مستقل تأیید نشده. `FEZI_WALLET_ADDRESSES_REVIEWED` باید پس از بررسی حضوری ادمین فعال شود؛ صرف فعال‌کردن آن خودکار پرداخت را راه نمی‌اندازد
- «Quantum wallet» نام دقیق کیف پول در درخواست مبهم است؛ بدون تأیید نام رسمی، به جای حدس از هشت گزینه شناخته‌شده استفاده شده است

## نصب روی cPanel Node.js

1. فایل ZIP را استخراج و با Node.js 22 اجرا کنید؛ `npm test`.
2. `APP_PASSWORD` و `SESSION_SECRET` منحصربه‌فرد در محیط هاست تعیین کنید.
3. `DATA_DIR` را خارج از پوشه عمومی سایت روی فضای پایدار قرار دهید.
4. `PUBLIC_BASE_URL` را به دامنه HTTPS واقعی تغییر دهید.
5. `OPENROUTER_API_KEY`، `HF_TOKEN` و `FEZI_RESELLER_OPENROUTER_KEY` را فقط در **Secrets** وارد کنید. به GitHub و ZIP عمومی کپی نکنید.
6. از `/admin/api-providers` وضعیت پیکربندی را ببینید. «configured_unverified» به معنی اتصال تست‌شده نیست.
7. پیش از قبول وجه واقعی، کلیدها و آدرس‌های ارسال‌شده در گفتگو را **rotate/revoke** و تسویه را توسط ارائه‌دهنده معتبر فعال کنید.

**هشدار:** ساخت سفارش شارژ هرگز نشان‌دهنده پرداخت واقعی یا اضافه‌شدن موجودی نیست. از کاربران برای آدرس‌های تأییدنشده پول دریافت نکنید.
